# dian-bridge 执行端部署

## 它负责什么

dian-bridge 是“癫影每日大包解锁”插件的配套浏览器执行端，需要部署在你自己的 NAS 或服务器上。

Muvyo 插件负责定时触发、交接登录信息、显示进度和返回通知内容；dian-bridge 负责浏览器运行、网站登录、解锁历史核对、每日额度和防重复提交。一次只处理一个任务，已确认成功的记录不会重复提交；不能确认结果时先查询历史。

执行端由两个容器组成：worker 对插件提供任务接口，browser 运行按需启动的浏览器。任务结束后会清理浏览器进程并请求回收空闲文件缓存。正常空闲时浏览器进程不会一直运行。

## 版本与准备

| 项目 | 当前配套版本或要求 |
| --- | --- |
| Muvyo 插件 | 癫影每日大包解锁 0.4.4 |
| Muvyo | 3.14.0 或以上 |
| dian-bridge | 推荐 0.4.4，协议 5 |
| 默认部署文件 | 目录挂载版 r1，数据保存在自己填写的两个宿主机目录 |
| 运行环境 | 支持 Compose 的 Docker，或 NAS 的容器项目管理器；可以拉取文件中的 Node 与 Selenium Chromium 镜像 |
| 网络 | Muvyo 能访问执行端的映射端口；执行端能访问所选网站 |

执行端 0.4.4 修复了癫影网站新版列表打开详情失败的问题。已经部署 0.4.3 的用户可按[原项目升级步骤](#升级与恢复)保留原地址、访问密码及存储配置。插件 0.4.4 检查的是协议 5，可以直接连接新执行端。插件帮助中的旧版本号源自首发时的部署说明。

## 1. 下载 Compose 文件

**[下载 compose.yaml](https://raw.githubusercontent.com/kzerghost/muvyo-addons/main/deployment/dian-bridge-0.4.4/compose.yaml)**

也可以[打开仓库中的文件](../deployment/dian-bridge-0.4.4/compose.yaml)，点击 Raw 后保存。请保存为 `compose.yaml`，不要把下载到的网页 HTML 当作 YAML 导入。

Compose 已包含运行所需的程序，会创建 `dian-bridge` 项目及 worker、browser 两个容器。无需创建额外源码目录、config.json 或初始化容器。

## 2. 创建数据目录并设置路径、密码

在 NAS 的文件管理器中创建两个专用空目录，例如：

```text
/volume1/docker/dian-bridge/data/profiles
/volume1/docker/dian-bridge/data/state
```

`profiles` 保存浏览器登录会话，`state` 保存任务和防重复提交记录。它们是宿主机上的真实目录，可以在 File Station 中找到。路径可以自己选择，但必须是不同的绝对路径，仅供本项目使用；不要填写整个共享文件夹、其他应用的数据目录，或让两个项目共用同一目录。

打开下载的文件，修改开头的这两行，使其与自己创建的目录一致：

```yaml
x-dian-profiles-path: &dian-profiles-path "/volume1/docker/dian-bridge/data/profiles"
x-dian-state-path: &dian-state-path "/volume1/docker/dian-bridge/data/state"
```

如果使用以上示例路径，这两行可以直接保留。填的是 **NAS或服务器的本机路径**，不是浏览器下载路径或 Windows 的共享访问地址。文件要求目录预先存在；路径拼错或目录未创建时，Docker 会报挂载错误，请先核对目录。

两个服务启动时只处理自己挂载的根目录所有权和所有者读写执行权限，然后降为普通用户，并检查目录是否可写。不递归更改已有文件，不需要手动设置 `777`。这一步不会搬迁旧卷，也不会删除目录中的持久数据。

接着找到访问密码这一行：

```yaml
DIAN_ACCESS_PASSWORD: "CHANGE_ME_TO_RANDOM_32_CHARACTERS"
```

把占位值替换为自己生成的密码：**24–128位，仅使用字母、数字、下划线或短横线，首位为字母或数字；建议随机32位。** 保留引号。稍后在插件“执行端访问密码”中填写同一个值。

密码用于校验并加密插件与执行端之间的任务请求。它不是网站登录密码；网站邮箱、网站密码在插件设置中分别填写。

如果NAS的8788端口已占用，可将 worker 的端口映射改成例如：

```yaml
ports: ["8789:8788"]
```

此时插件连接宿主机8789端口，容器内端口仍是8788。

## 3. 在 NAS 或 Docker 中创建项目

### 群晖 Container Manager

1. 将修改好的 `compose.yaml` 放在准备保存项目文件的目录。
2. 打开 Container Manager → 项目 → 新增，选择该目录和已有 Compose 文件；不同 DSM 版本的导入入口名称可能略有差异。
3. 项目名使用 `dian-bridge`，创建并启动项目，等待镜像下载和两个服务健康检查完成。
4. 检查 worker、browser 两个容器均正常运行。首次拉取镜像可能需要较长时间。

### Docker Compose

在保存 `compose.yaml` 的目录执行：

```sh
docker compose -f compose.yaml up -d
docker compose -f compose.yaml ps
```

两种方式选择一种即可。浏览器服务只在项目内部提供接口，插件使用 worker 的映射端口。

## 4. 把地址填回插件

打开 Muvyo 中的插件设置，填写：

| 设置项 | 填写方法 |
| --- | --- |
| 执行端地址 | `http://NAS地址:8788/api/v1`，将“NAS地址”替换为 Muvyo 能访问的NAS或服务器地址 |
| 执行端访问密码 | 第2步写入 `DIAN_ACCESS_PASSWORD` 的同一个值 |

如果改用8789映射端口，地址对应为 `http://NAS地址:8789/api/v1`。必须保留末尾 `/api/v1`。填写的是从 **Muvyo 所在环境** 可以访问的地址；公网地址需按 Muvyo 要求使用HTTPS。

地址保存和联网限制由 Muvyo 检查。外部端口能够在你的电脑打开，不一定代表 Muvyo 容器也能访问；连接失败时先核对两者之间的网络和防火墙。

然后按[插件使用说明](DIAN.md)填写网站登录、300秒时限、每日执行时间与通知。

## 登录资料和记录存在哪里

| 宿主机目录（默认值） | 内容 | 更新时如何处理 |
| --- | --- | --- |
| `/volume1/docker/dian-bridge/data/profiles` | 浏览器登录会话、Cookie、站点本地存储及浏览器自身缓存 | 保留 |
| `/volume1/docker/dian-bridge/data/state` | 任务结果、账号身份指纹、每日解锁与防重复提交记录 | 保留 |

如果修改了文件开头的路径，以自己填写的路径为准。默认目录挂载版不会创建 `dian-bridge_profiles`、`dian-bridge_state` 命名卷，也不把这两类数据留在容器可写层中。

**删除项目、删除容器、重新下载 Compose 或执行 `docker compose down`，都不会自动删除这两个宿主机目录。** 执行端目前没有按天清除历史任务记录或自动删除整个浏览器资料目录的功能，需要自己关注目录占用。任务结束后的进程退出和空闲内存回收，处理的是运行内存，不等于清除磁盘数据。

### 备份与卸载

- **备份**：等待任务结束，在插件中暂时关闭自动运行并停止执行端项目，再复制两个完整目录；妥善保存访问密码和原 Compose。备份可能含登录会话，应按账号资料保管。
- **恢复或重建**：恢复两个目录及其中的文件所有权、权限，在 Compose 中指向原路径，保留原访问密码后启动。启动程序不会递归修复备份中已有文件的所有权；出现权限错误时，应先核对恢复方式和原文件权限。
- **暂时停用**：关闭自动运行并停止项目，保留目录，后续可以继续使用。
- **彻底卸载**：先关闭插件自动运行、确认没有待核对的任务，再删除执行端项目。确实不再需要会话和记录时，最后自行删除这两个数据目录。不要通过清空 `state` 来重试结果未知的提交。

### 已有命名卷部署

旧版使用 Docker 命名卷，默认名称为 `dian-bridge_profiles`、`dian-bridge_state`，部分早期配置使用过自定义名称。删除旧容器通常仍会保留这些卷。

使用命名卷的用户可下载 [0.4.4 命名卷版](../deployment/dian-bridge-0.4.4/compose.named-volumes.yaml)，将原项目名、访问密码和两个卷的映射带入新文件。使用前请确认解析出的卷名与原部署一致。

**切换到默认目录挂载文件不会复制旧卷内容。** 需要保留登录和台账时，应停机备份并迁移两个卷的完整内容及所有权后再切换；完成核对前保留旧卷。打算彻底全新部署时，也要先确认旧任务结果，再单独清理属于旧项目且没有任何容器引用的卷。不要执行全局卷清理。

### 运行权限

默认目录挂载版以root进行挂载根目录的短暂初始化，然后将 worker 降为UID/GID `1000:1000`、browser 降为镜像自带的 `seluser`；业务进程会校验自己已降权且有效、保留 capabilities 均为空。初始化及负责信号转发的init仅保留目录所有权、切换用户/组和发送停止信号所需的能力，不挂载Docker接口。健康检查也会先降权。

worker 根文件系统只读；browser 需要可写运行环境。两个服务限制提权。Compose 默认启用 `BROWSER_NO_SANDBOX=true` 以兼容部分NAS内核；这会关闭 Chromium 自身沙箱，容器隔离仍保留。

## 升级与恢复

### 从 dian-bridge 0.4.3 升级到 0.4.4

1. 等待当前任务结束，暂时关闭插件的每日自动运行，并保留一份原 Compose。
2. 下载与当前存储方式相同的 0.4.4 Compose。把原项目名、`DIAN_ACCESS_PASSWORD`、端口映射，以及原 `profiles` 和 `state` 路径或卷映射填入新文件。
3. 替换原项目的 Compose 并重建容器。群晖可在 Container Manager 中更新并重建原项目。命令行可在原项目目录执行 `docker compose -f compose.yaml up -d`。普通重启仍会运行旧容器内的程序。
4. 检查两个服务均健康。打开 `http://NAS地址:8788/health`，按实际端口查看 `version` 为 `0.4.4`、`protocol` 为 `5`。随后恢复每日自动运行，查看下一次运行结果。已装的插件 0.4.4 可以继续使用，原登录会话、任务和防重复记录会通过持久存储复用。

### 恢复与故障记录

执行端如需回退，可使用备份的原 Compose 重建，保留同一份数据和访问密码。[旧版部署文件](../deployment/dian-bridge-0.4.3/)仍可查阅。0.4.3 遇到新版大包列表时仍会出现详情导航失败。

遇到任务故障请保留原任务记录。宿主重试时会先查旧任务与网站历史。插件版本恢复与执行端独立，普通仓库安装不支持直接降级插件。

当前没有承诺一键自动回退。遇到问题可在仓库提交 Issue，并附版本、脱敏错误和发生时间。
